# 和田研フォント：原典骨格からのリアルタイム生成

現在の比較画面は、CLWFKの文字定義と丸ゴシック生成コードを使います。完成フォントの画像からの骨格抽出は使用しません。原典の点座標を時間に応じて動かし、原典の数式から得た中心曲線を一定幅のSVGパスとして同じ要素へ反映します。録画、画像列、完成画像への差し替えはありません。

## 起動・操作

`node server.mjs` または `START.cmd` で http://127.0.0.1:4184/ を開きます。閲覧時の計算はブラウザ内のJavaScriptだけで実行され、サーバーは静的ファイルを配信します。Javaは閲覧時には不要です。

共通入力・個別試打・文字サイズ・拡大・再生速度・静止比較を使えます。比較画面はCからC＋5までの6案です。点や円を中心線抽出の結果で分類せず、原典の画種として扱います。ひらがなの補間点を個別の折れ角と見なす処理も行いません。

試打欄への追加入力では共通する既存文字のSVG要素と登場時刻を保持し、新しく加わった文字だけを開始状態から動かします。長文のペーストは生成処理を短い時間単位で区切って途中結果を表示し、文字同士を少し重ねながら一定間隔で左上から順に進めます。途中編集で後方の文字を再利用する場合も登場時刻を前から順に補正するため、文章の後半だけが空欄を飛び越えて先に表示されることはありません。削除や途中編集でも、変更されていない前後の文字は再生成しません。「全て再生」を押した場合だけ全体の登場時刻をリセットします。

C＋4とC＋5′の文字間リレーは、空白、改行、未収録文字による空欄を越えても時間順を保持します。空欄の直後にある後半の文章が、前半の進行を追い越して開始することはありません。

上部の「貼り付け」はクリップボードの全文で共通試打欄を置き換え、全パターンへ反映します。

`/clock` はC＋5を0.75倍相当で使う時計ページです。原典に骨格を持つ全角数字と全角コロンをSVGパスで描き、変わる桁では旧字形を畳む処理と新字形を開く処理を重ねます。時・分・秒は端末の現在時刻に追従します。

初期読み込みの原典JSONはgzipで配信し、ETagによる再検証を使います。一時的な通信失敗はブラウザ側で最大3回再試行します。

横画に指定された点と接続点は固定します。共有する点には同じ座標を与えます。円の形は原典の専用関数で生成し、配置だけを動かします。このモーション設計は本アプリで追加したもので、原典にアニメーションが収録されているという意味ではありません。

## 移植の構成

- `engine/clwfk/`：固定リビジョンの元コードと元文字定義。著作権表示を保持。
- `engine/compatible/`：Unicode Lispで読むための文字コード・シンボル互換コピー。
- `engine/export-browser.lisp`：元コードのマクロを展開してブラウザ用プログラムを書き出し、部品合成・正規化を済ませた文字骨格を出力。
- `web/source-program.json`：原典生成処理の構文データ。独自の丸線レンダラーに置き換えたものではありません。
- `web/source-vm.js`：使われているLispのリスト・属性・動的変数・制御構造などをJavaScriptで実行する互換層。完全なCommon Lisp処理系ではありません。
- `web/source-fast.js`：原典lib.lのベクトル計算を同じ式で直接JavaScript化したもの。
- `web/source-glyphs.json`：6,703文字定義の正規化骨格。点属性、画種、点参照、接続属性を保持。元の合成定義もLisp文字列として保持。
- `web/source-engine.js`：骨格の変形と原典生成処理と、原典の中心曲線を骨格に沿わせる変形。DOMに依存しません。
- `web/native-renderer.js`：生成結果を画面内のSVGへ反映。見えている範囲だけを表示します。

原典処理では、書体用の前処理、画種ごとの中心曲線、LINKを使った接続を実行します。表示線幅は原典の丸ゴシック幅8を中心線の両側へ適用した16で固定します。アニメーションのフレーム列は保存・再生しません。

部品の合成と正規化はビルド時に元のLisp処理系で行っています。毎フレームはCの変形関数とC＋系の追加規則で中心曲線を動かし、SVGストロークを更新します。部品合成のパラメータ自体をブラウザUIで編集する機能、およびC#だけで動くUnity実装は未実装です。

## 検証

- `node verify-source.mjs`：7文字についてABCLで実行した原典の輪郭と比較。輪郭構成・点の種類が一致し、最大座標差は400単位の字面に対して0.00005未満。
- `node verify-native.mjs`：同じ7文字の複数の変形時刻で原典生成が有限な輪郭を返すことを確認。
- `node verify-coverage.mjs --all`：全文字の完成時・途中時の生成検証。結果は `source-audit/browser-coverage.json`。
- ブラウザではCanvas画像処理を例外にした状態で1,200文字の入力を試験。SVGパスの変化、停止前後の要素の同一性、画面外の文字の間引き表示を確認。

計算量は字形の複雑さと同時に動く文字数に依存します。60fpsを全端末・全文字で保証する実装ではありません。

## 文字の範囲・ライセンス

対象は元キットに読み込まれる文字定義です。後年の「和田研細丸ゴシック2004絵文字」の追加文字まで元スケルトンがあると見なしてはいません。未収録文字や生成エラーは画面に表示し、別フォントや画像抽出で補いません。ASCII英数字は古いCLWFKの全角字形へ置換せず、同梱する「和田研細丸ゴシック2004絵文字」TTFのベクター輪郭を使います。`engine/export-ttf-ascii.mjs` がビルド時に輪郭をSVG命令へ変換し、ブラウザでは画像化せず同じSVGパスを表示します。

原典の計算式・分岐順を維持し、交差判定、接続の参照、行列計算などの頻出処理をJavaScriptへ直接移植しました。互換実行器も関数本体・引数処理を初回に準備し、リスト走査の繰り返しを削減しています。画面外の比較カードと、拡大表示の裏側のカードは描画しません。判断点が非表示ならガイド描画も実行しません。

修正前と修正後の277文字×7状態（完成形、両モードの畳み量0.15・0.6・1）のSVG文字列が完全一致しました。原典との7文字の座標比較も合格。ローカルNodeで「あ永木林あいうえお和田研」を30回生成する同一条件では、1巡平均88.1msから37.7msへ短縮しました。これは計算時間の計測で、スマートフォンのフレームレート保証ではありません。

## CからC＋5

Cは `structure.js` のrule 11を使います。原典が持つLINK接続と、原典の数式で作った中心曲線の交点から枝を構成します。分岐のある部分では最長の連続経路を骨格として残し、長い縦画全体が横へ倒れるのではなく、そこから出る短い枝が接続点で動きます。Cはその枝の曲がり角も順に開きます。

Cはトリムなしのまま残しています。別案C＋では、中心曲線の累積回転量、曲がる向きの連続性、曲線長に対する始終点間距離から円弧の画を判定します。「の」や「あ・め・ぬ」の回り込む画は完成位置から回転させず、SVGの中心曲線に沿ったトリムだけで登場します。交点で分けた枝ごとにはトリムせず、原典の一画を一つの連続パスとして一度だけトリムします。円弧以外の画はCの関節運動を保ちながら、支点から長さ0の状態で伸びます。ただし文字内で最長の直線画は主軸とし、完成時の向きを変えずに軸方向へ伸ばします。このため「ト」の長い縦画は回転しません。文字コードや文字一覧による決め打ちは行いません。

C＋2はC＋を残した差分です。一画の曲がる向きが揃い、総曲率が一定以上あり、端に十分な長さの直線区間を持つ開いた弧を検出します。直線区間の方向を固定し、残りの各線分の相対角度を根元から先端へ順番に戻すことで、最初は直線の延長にある線が弧へ展開します。「し」の縦部分は回転せず、下端から右上がりの曲線が形成されます。文字コードによる例外指定はありません。

C＋3は、共有点で接続する画をグラフ化し、各連結成分の最長画を幹として選びます。幹を先に伸ばし、交点から一段目、二段目の枝を順番に長さ0から開きます。C＋4は各画の両端について、前画の終端からの距離と接線角度の差が最小になる向きを選び、その順序で画を受け渡します。C＋5は閉路を構成する画のうち最後の画を後半まで長さ0に保ち、単独の回り込む一画では曲率と全長を同時に増やして最後に輪を閉じます。

C＋5′はC＋5を残した差分です。C＋4が求めた接線の受け渡し順と各画の始点を使いながら、閉路を完成させる画だけを列の最後へ送ります。C＋5の大きな閉じ方を保ち、画が始まる理由を前画との接続で読めるようにしています。

C＋3、C＋4、C＋5はSVGの `stroke-dasharray` を使いません。パス座標を支点へ集めた長さ0の状態から変形し、ゼロ長の間は丸い線端も表示しません。

表示は全フレームで同じ中心曲線と `stroke-width="16"` を使います。C＋のトリムも同じSVGストロークの `stroke-dashoffset` だけを変えるため、途中だけ細い輪郭になることはありません。原典の `skeleton2list` による塗り輪郭生成は、元データとの照合と有限性検証のために残しています。

原典でoutline型のみの記号は中心骨格を持たないため、その原典パスを一定幅の線で表示します。これを通常の中心骨格と同一とは扱いません。

`node verify-motion.mjs` は160文字の基礎変形、時間配分、複数時刻を確認します。`node verify-round.mjs` はC＋とC＋2について円弧、直線軸、一画一パス、完成形への一致を確認します。`node verify-coverage.mjs --all` は6,703文字で生成・途中の有限性を確認します。
