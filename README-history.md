# 和田研細丸ゴシック・登場アニメーション

`START.cmd` を開くと http://127.0.0.1:4184/ が起動します。Node.jsが必要です。通常の画面は白地の文字と左上のⓘだけです。画面をクリックして入力してください。日本語は変換確定後に登場します。

文字は左上から右へ並び、端で折り返します。新しく入力した文字が0.14秒ずつずれて、折り畳まれた状態から1.35秒で開きます。既存の文字は残り、繰り返し再生しません。改行・削除・追加入力に対応します。表示領域を超えると文字サイズを下げます。入力はUTF-16で512文字分までです。

## 使用フォント

配布元の **和田研細丸ゴシック2004絵文字 4.73** のTTFを変更せず同梱しました。旧CLWFKの丸ゴシックへの置換ではありません。

- ライセンス：`web/font/LICENSE.txt`（配布物の説明・使用条件全文。文字コードのみUTF-8化）

## 動きと移植

実TTFをブラウザで描画 → 中心線の細線化 → 接続グラフ → 関節列 → ウェイト付きメッシュ、という処理です。完成時は元のフォント画像に戻ります。太さのアニメーションではありません。

`web/fold-core.js` はDOM・描画APIに依存しない数値計算です。`buildRig` の `jointLength` で関節間隔、`pose` の `bend` で曲げ量を変更できます。登場間隔は `entryTimes`、登場時間は `renderer.js` の1.35秒です。骨格は画像から自動推定したもので、原典の意味付き骨格や筆順データではありません。自動ウェイトによる変形のため、交差部や複雑な字形の途中形状には歪みが残る場合があります。

`web/export-rig.js` の `exportGlyph(grapheme)` は関節・ウェイト・三角形を含むrigとPNGマスクを返します。生成済みrigをJSONで保存し、PNGとともにUnityへ渡せます。

`unity/FoldPose.cs` は同じ関節計算とメッシュ変形のC#実装です。`FoldRig` にJSONを読み込み、`FoldPose.Evaluate` の出力XYをMesh.verticesへ反映します。座標は256×256、Y下方向。UnityではY反転、UVのV反転、両面透明マテリアルを使用してください。元の輪郭をPNGで持ち、頂点とUVを対応させます。Unityエディターでの動作検証は未実施です。

参考：https://x.com/yugop/status/2062481427233685661
参考動画の実装を移植したものではなく、線が折り返しながら文字になる登場の方向性を参考にした実装です。

## 検証

`node --test verify-fold.mjs`

実フォントのハッシュ、追加文字の収録、完成時の座標一致、関節長の維持、数値の有限性、追加入力・削除で既存の登場時刻が維持されることを確認します。全23,909字形の目視検証は行っていません。

旧CLWFK方式は `server-clwfk.mjs` と `README-clwfk.md` に保存しています。現在の `START.cmd` はTTFを使う新しい画面を起動します。旧 `verify.mjs`、`web/preview.html`、`example-animation.json`、`unity/WadalabMotionPreview.cs` はCLWFK方式用で、現在の画面の動きとは異なります。
調整値は `web/motion-config.js` にまとめています（登場時間、文字間の遅延、曲げ量、関節間隔、メッシュ分割、文字サイズ）。

## 現在の登場動作：パストリミング

現在は折り畳みを使わず、実フォントから抽出した中心線のパス長に沿って表示範囲を伸ばします。字形の座標と大きさは固定です。一文字の最大登場時間は0.35秒、次の文字の開始まで0.07秒。調整先は `web/motion-config.js` です。順序は幾何学的なパス順で、正しい筆順データではありません。

`buildTrimMap(alpha, width, height)` は描画APIに依存しない計算で、各画素の登場位置を0〜1で返します。原字形のアルファ値を保ち、`progress` がこの値を超えた画素を表示します。完了時は元のアルファ値をそのまま使用します。Unityでも同じマップをテクスチャのRチャンネル、元字形をAチャンネルに入れ、同じ閾値式で再生できます。以前の関節用C#コードはこの新しい登場動作には使用しません。

## 現在の比較画面

`/` は構造判断による10案の共通入力・個別試打・再生画面です。最大登場時間は一文字0.35秒、開始間隔0.07秒。`/single` は元のパストリミングです。

2026-09-13: 画像メッシュ変形と、連結部分に共通して加えていた回転を廃止しました。`LineRenderer` は変形した中心線を丸い線端・接合部で直接描画します。閉じた経路にも面の塗りつぶしを使いません。3番は根元を固定し、末端側の関節を曲げます。各規則で静止するはずだった線は、両端を固定して局所的にしならせます。孤立点は短い移動を加えます。構造固有の枝・閉路回転は該当する案に残しています。

中心線と線幅は実際の和田研フォント画像からの近似抽出です。途中形は再構成した線、完成形は変更していない元TTFの描画です。最後の35msで元字形へ切り替えます。意味付きの筆順や部首データではありません。

`web/structure.js` の analyze / plan / posedPaths / posedDots は描画と独立した数値処理です。Unityへの移植はグラフ・規則・出力経路を利用できます。既存の unity/FoldPose.cs は旧方式で、今回のC#移植は未実施です。

検証: `node --test verify-structure.mjs verify-fold.mjs`。ブラウザでも「木田永あ口一。i𠮷😀」×10案の670パスについて動き・有限値・完成座標、3番の根元固定を確認しています。

登場開始時は完全非表示です。変形後の経路を弧長でトリムし、登場時間の85%までに全長を表示、残りで完成形へ落ち着きます。孤立点はサイズ0から登場。判断点は初期非表示です。

## 06シリーズ（現在のトップ画面）

Aは現行06、Bは06の変形からトリムのみ除去、Cは横軸を固定して枝の根元と角を同時に開く、Dは根元から角を順に開く、Eは現行10の比較用です。全欄で個別試打できます。A・Eだけ従来のトリムを残します。

C・Dは元の横線判定を利用し、非閉路の枝について実際の角度差が0.30radを超える頂点を関節にします。Dは根元の回転を先行させ、角の順序に従って開始をずらします。各区間の長さは保持。固定軸へのしなり追加は行いません。横線判定は経路両端の水平・垂直距離比較による近似で、筆画や部首の意味を理解した判定ではありません。

`node --test verify-series.mjs verify-structure.mjs` で完成形・固定軸・区間長・同時と順次の差を検証しています。

## F：隣の文字への受け渡し

Bの変形を維持してトリムなし。各経路の開始点のx位置で文字内部の開始をずらします（最大で登場時間の35%）。最も右へ到達する経路の開き進行が60%に達する時刻を計算し、次の文字の開始条件にします。空白・改行は連鎖を切ります。文字列の折り返しでは読み順に引き継ぎます。静止比較は各文字の同じ進行度の形を比較する機能なので、文字間の受け渡しは再生で確認してください。

`relayProfile` / `relaySchedule` / `relayPaths` はDOMから独立した数値関数。物理的な接触ではなく、経路の位置と開き進行による連鎖です。`node --test verify-relay.mjs verify-series.mjs` で受け渡し時刻、空白での切断、左右の順序、完成座標を検証済みです。

## 長文の描画修正

文字サイズ指定時のCanvasは表示領域の高さに固定し、スクロール位置に見えている字形だけを描画します。全文の高さは空のスペーサーで保持するため、文字数に比例した巨大なビットマップは作りません。文字準備は16字ごとに処理を譲り、個別入力の開始時計は準備後に取得します。再生ボタンはスクロール位置を先頭へ戻します。

ブラウザで1200文字を検証。全文高さ103704pxに対してCanvas高さ250pxを維持し、再生中のピクセル変化・末尾の表示・準備後の開始時刻を確認。実際のB試打欄でも1200字の配置とエラーなしを確認しました。

## 現在の文字表示：ネイティブSVG

比較画面の文字はHTML内のSVG `<path>` です。毎フレーム同じ要素の `d` 座標を更新し、完成時にも同じ要素・線幅で残します。Canvasへの文字描画、完成時の元字形ビットマップへのクロスフェードは廃止しました。録画・画像列は使用しません。長文では表示付近のSVG要素のみDOMに保持します。

字形の準備は引き続き実フォントを一度ラスタライズして中心線と幅を近似抽出しています。完成形もこの中心線のベクター描画なので、元TTFのアウトラインとの厳密な一致は保証しません。以前の「完成形は元TTFの画像へ切り替える」という記述は旧実装です。`/single` の旧トリム画面は別実装です。

1200文字で、パスのd属性の変化、再生中と完成時のDOM要素の同一性、SVG内の画像要素ゼロ、末尾へのスクロール表示をブラウザ検証しました。

## 元の生成コードの調査結果

`source-audit/audit.md` に、原典の文字定義・書体継承・合成・接続・肉付けの調査を記録しました。`source-audit/source-glyphs.json` は7文字を元コードで展開したデータです。現在の比較サイトは依然として画像から近似抽出した骨格を動かす試作であり、原典生成アルゴリズムのブラウザ移植はまだ接続していません。この違いを混同しないでください。
